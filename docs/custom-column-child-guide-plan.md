# カスタムColumn 子Guide展開メモ

親記事：`data/articles/columns/modern-car-custom-regret-reason-column.json`

このColumnは、現代車カスタム全体の入口記事として扱う。
特定メーカー、特定車種、特定部品の深掘りは、親記事に詰め込みすぎず、子Guideで個別に作る。

## 子Guide予定

以下の5本は、`status: draft` / `publicState: draft` として先に用意する。
本文、出典、画像、内部リンクが完成するまで公開しない。

1. `electronic-damper-coilover-risk-guide`
   - 電子制御ダンパー付き車に車高調を入れるリスク。
   - 警告灯、キャンセラー、アライメント、純正戻し、売却まで深掘り。

2. `tv-canceller-can-risk-guide`（既存公開Guideを現行基準へ統合更新）
   - TVキャンセラーとCAN通信の関係。
   - 物理割り込み型、コーディング型、診断ログ、保証、入庫対応まで深掘り。

3. `aftermarket-air-cleaner-risk-guide`（既存記事へ統合済み）
   - 社外エアクリーナーとセンサー・燃調の関係。
   - エアフロー、吸気温度、燃調補正、EVAP、アイドリング不調まで深掘り。

4. `adas-lowered-car-aiming-risk-guide`
   - ADAS付き車をローダウンするときの注意点。
   - カメラ、ミリ波レーダー、エーミング、車高変化、バンパー交換まで深掘り。

5. `used-custom-car-check-guide`
   - カスタム済み中古車の見分け方。
   - 純正戻し、施工履歴、書類、警告灯、配線、試乗時の違和感まで深掘り。

## 画像制作ルール

画像は後で作る。
本文を先に決めてから、画像の役割、挿入位置、キャプション、制作プロンプトを決める。

画像化するのは、レイアウトやカードだけでは読者がイメージしにくいものに限る。

例：
- 部品の実物。
- エンジンルーム内の配置。
- OBD診断機やエラーコード。
- 修理中、測定中、エーミング中の工程。
- センサー、レーダー、配線などの位置関係。

画像化しないもの：
- ただの確認項目。
- 条件整理。
- NG / OK比較。
- 進め方の順番。
- FAQ。

これらはカード、表、フローで表現する。

## 文章ルール

- 普通の車記事の口調を維持する。
- 具体例は削らない。
- 内容が重くなる場合は、画像、カード、表、内部リンクで視認性を補う。
- 句点「。」ごとに本文を改行する。
- FAQ質問、ボタン、ナビ、ラベルなどのUI部品には機械的な句点改行を当てない。
- 特定メーカー・特定車種の話は、根拠と条件を添える。
- 「頻発」「必ず」「拒否される」などの強い断定は、出典や明確な根拠がある場合だけ使う。

## 親記事と子Guideの深度分担

親記事では、判断に必要な共通知識まで扱う。
ただし、車種別、部品別、診断値、故障例、施工方法、具体的な数値確認は子Guideで扱う。

親記事に残す内容：
- 何が問題になるか。
- どの場面で困るか。
- 最低限何を確認するか。
- どの子Guideに進むべきか。

子Guideで扱う内容：
- 特定車種、特定メーカーの事例。
- OBD数値や診断項目。
- 施工手順。
- 部品方式の比較。
- 警告灯や不具合の切り分け。

親記事は薄い概要にしない。
読者が親記事だけでも基本判断できる深度を保ち、さらに詳しく知りたい論点を子Guideへ送る。
