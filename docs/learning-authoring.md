# 会話教材の追加と確認

クルマ全体を扱う参考書として、教材を `data/learning/*.json` に保存します。エンジン、吸気・排気、足回り、タイヤ・ブレーキ、電装・安全装備、メンテナンスのテーマを `lib/learning.ts` で管理します。教材の登録は同ファイルの `authoredCourses` で行います。

## 読者の入口と進み方

表示名は「はじめて」「しくみと選び方」「深く読み解く」。データ上のキーは順に `start`、`mechanism`、`evaluation` です。知識量を数値で区切るラベルは画面へ出しません。単位・測定値・計算式は必要な文脈で正確に記します。

各講座はこの順序で進み、各回に学習目標、シュナと莉奈の会話、理解に役立つ図表、持ち帰る要点、確認問題、答え、復習先、資料の参照を入れます。`prerequisites` は同じ講座の前の回、`checkpoint.review` は現在または前の回へ向けます。前後リンクは配列順から生成されます。新しい回の追加で既存の slug を変更しません。

- `dialogue`：疑問と説明。二人とも各回に登場させ、キャラクターの発言だけを専門資格の根拠にしない。
- `flow`：手順・因果の流れ。各ステップの見出しと本文、条件や限界の注記を記す。
- `comparison`：見方をそろえた比較表。すべての行のセル数を見出し数と一致させる。
- `measurements`：同じデータからグラフと数値表を表示する。単位、横軸・縦軸の意味、系列名、条件を記す。各系列の値の数を `rounds` と一致させる。数値横軸は厳密に昇順の `xValues` を同数指定し、実際の数値の間隔で描く。省略するとカテゴリを等間隔に並べる。小さな差を拡大する場合は全点を含む `yRange: [最小, 最大]` を指定し、注記にも0起点でないことを書く。実測・仮定からの計算・説明用の架空データを明記する。
- `diagram`：登録済みの模式図を表示する。種類を増やすときは型、図の表示、検索用の説明、検査を同時に追加する。

## 出典と日付

`course.sources` に資料 ID、正式名称、https URL、参照範囲の注記を登録し、各回の `sources` から ID で参照します。公開時には実際の資料を開き、引用する主張・適用車種・測定条件まで確かめます。ある製品の結果を別の製品や全車へ一般化しません。

`updatedAt` は教材本文の公開・実質的変更日です。`verifiedAt` は資料を確認した日で、確認だけで本文を変えていないときは `updatedAt` を進めません。サイトマップの `lastmod` は `updatedAt` から作り、ビルド日を使いません。新規教材に同じ公開日が並ぶことはあり、その場合も生成値と原稿日付を照合します。

## 公開と検索

公開条件は `lib/content/publication.ts` の `publicationPolicy` に従います。`published` と `index` は公開・検索エンジン用サイトマップの対象です。`published` と `noindex` は閲覧とサイト内検索ができ、サイトマップには載りません。`draft`、`archived`、`redirect` は教材一覧・詳細・サイト内検索へ出しません。公開指定の JSON をアプリに登録し忘れるとテストが失敗します。

URL は `/learn`、`/learn/<course>`、`/learn/<course>/<lesson>` です。テーマ・段階による `/learn` の絞り込みは動的にサーバー描画し、絞り込み URL は noindex、canonical は `/learn` とします。講座・各回の本文は静的 HTML へ出します。検索は本文、図表の文字、軸名、要点、問題と答えまで対象にします。検索用の内部全文は検索 API の JSON に含めません。

`relatedGuideSlug` は公開中の既存ガイドのみ、`selectionHref` は実在する `/choose` の選び方ページのみを指定します。既存ガイド・車種・コラム・系譜の記事 URL を学習 URL にまとめてリダイレクトしません。

## 確認手順

1. `node --import tsx --test tests/learning.test.ts tests/publication.test.ts tests/search.test.ts` で、原稿構造・学習順序・公開方針・本文検索を確認する。
2. `npm run verify:links` で既存記事と教材の内部リンクを確認する。
3. `npm run check` で lint・構造・全テスト・ビルド・実 HTTP 検証を行う。ビルド後は既存記事の全文検査に続いて学習記事の全文・会話数・図表・問題・出典・前後リンク・canonical・robots・サイトマップを照合する。
4. ビルド後に学習部分のみを再確認する場合は `npm run verify:learning`。原稿変更後は先にビルドし直す。
5. ブラウザーでホームから六つのテーマ、三つの入口、目次、前後移動、復習、検索、選び方と既存ガイドを実際にたどる。狭い画面で横はみ出し、表とグラフ、キーボードでの開閉を確認する。

自動検査は根拠の正しさや理解しやすさを保証しません。一次資料との照合、通読、画面確認、実際の読者による理解の確認を分けて記録します。ローカル検証・GitHub への保存・本番公開はそれぞれ別の状態として報告します。
